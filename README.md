# note運用

note と Threads の運用を、6つの担当に分けて回すための仕組み。
各担当は Claude Code のスキルとして定義してあり、スラッシュコマンドで呼び出す。

## 担当一覧

| | 担当 | コマンド | 短縮 | やること |
|---|---|---|---|---|
| ❶ | 投稿担当 | `/note-post` | `/投稿` | Threads投稿を10本一括生成（型を10種散らす） |
| ❷ | ライター | `/note-write` | `/執筆` | note本文を8,000字で執筆 |
| ❸ | 編集担当 | `/note-edit` | `/編集` | AI臭い言い回しを洗い出して修正 |
| ❹ | 分析担当 | `/note-analyze` | `/分析` | 伸びた投稿を分析して次に活かす |
| ❺ | 企画担当 | `/note-plan` | `/企画` | 次に書くテーマの候補出し |
| ❻ | 販売担当 | `/note-sell` | `/販売` | タイトル案と有料ラインの設計 |

**何をやればいいか分からないときは `/note`。**
今の状況（数値の記録漏れ・書きかけの原稿・投稿在庫・テーマの有無）を見て、
次にやる担当を1つだけ選んで提案する。

## 自動運営

`/自動`（= `/note-auto`）で ❺→❶→❷→❸→❻ を一気に回す。
企画・Threads10本・本文8,000字・編集・タイトル/価格/有料ライン設計までが
`note/output/YYYY-MM-DD/` に揃う。

### 自動化できる／できない

| | |
|---|---|
| ✅ できる | 企画、Threads10本、本文8,000字、AI臭さの検出と修正、タイトル20案、価格、有料ライン位置 |
| ❌ できない | **note・Threadsへの実際の投稿**（noteに外部投稿APIが無い／Threadsは個人トークンが必要） |
| ❌ できない | **数字の取得**（インプレッション・スキ・購入数は `/分析` に貼る） |
| ❌ やらない | 分からない数字を埋めること。`【要確認】` で穴を空けたまま出す |

つまり自動化後に残る手作業は **「投稿する」「【要確認】を埋める」「数字を貼る」の3つだけ**。

## 回し方（1サイクル）

```
❺企画 → ❶投稿(反応テスト) → ❷執筆 → ❸編集 → ❻販売設計 → 公開 → ❹分析 → ❺企画 …
```

ポイントは2つ。

1. **❶を❷の前に置く。** Threadsで先に反応を見てから8,000字を書く。反応がゼロのテーマに8,000字かけない。
2. **❹の結果を `note/voice.md` に書き戻す。** 書き戻さない分析は次に活きない。

## 設定

`note/voice.md` に、発信者プロフィール・読者・文体・禁止事項・商品をまとめてある。
全担当がここを読む。書き方を変えたいときは、各スキルではなくこのファイルを直す。

## ファイル配置

```
note/
  voice.md              全担当が参照する設定（読者・文体・実績・商品）
  themes/backlog.md     企画ストック / 既出テーマ管理
  drafts/               note本文の原稿
  threads/              Threads投稿案（日付ごと）
  analytics/log.csv     投稿ごとの数値ログ
.claude/skills/         各担当の定義（実体）
.claude/commands/       /note と日本語ショートカット
```
