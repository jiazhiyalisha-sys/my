# 毎晩の指示（❹｜無人運転）

このファイルの手順を、**人間の返事を一度も待たずに**最後まで走らせる。
確認・提案・選択肢の提示は禁止。全ての分岐に既定の答えが書いてある。

---

## 手順

### 0. 読む（❺）
1. `note/ログ.md` を最後まで読む
2. `note/型.md` を読む
3. `note/禁止表現.md` を読む
4. `note/素材.md` を読む

ログの最新回の「落とす要素」に入っている手は、今回使わない。
「外れ」判定の仮説は再提出しない。「保留」の仮説はそのまま再提出してよい。

### 1. 型を確認（❶）
型は `note/型.md` の T1〜T8。**再分析はしない。**
ただしログに3回分以上の販売数が溜まっていたら、実績が型と矛盾する条件を1つだけ書き換え、
その旨をログの「分かったこと」に1行残す。

### 2. 3本の目次を作る（❷）
枠は素材から決める：
- **本1・本2** `素材.md` の失敗のうち、金額・人数・年数が大きい2件をそれぞれ1本に
- **本3** 仮説枠（→ 手順3）

素材に失敗が1件しかなければ2本にする。0件なら本3のみ出す。
※第1回の固定枠（本1=仕事／本2=人）は、素材の人・関係スロットが全て空だったため廃止した

制約：
- 中身は `note/素材.md` のスロットのみ。**書かれていないことは書かない。創作・推測・一般論での穴埋めは禁止**
- 空スロットの章は削除する。残り章が4未満になった本は出さず、「素材不足：S◯」と記録する
- `note/禁止表現.md` の語・構文は1つも使わない。使いたくなったら別語に置換し、置換できなければ章ごと書き直す
- 出力先：`note/出力/YYYY-MM-DD.md`（実行日の日付）

### 3. 本3を仮説に振る（❸）
本文の**前に1行**、`今、〜が求められているのではないか。` の形で仮説を置く。
- 仮説は10本にも過去ログにも無い切り口であること
- 答えが出ていないこと。出ている話は仮説枠に置かない
- 本3のみ T4（過去形・決着済み）を外してよい。結論を出さずに閉じる

### 4. ログに追記（❺）
`note/ログ.md` の末尾に、ファイル冒頭のテンプレートをコピーして新しい回を追記する。
- タイトル3本と、本3の仮説文を必ず書く
- 販売数がまだ無い回は「保留」
- **過去の行は書き換えない。追記のみ**

前回以前の回に公開済みの記事があり、数字が取れていれば、その回の行を埋めて判定する。
判定基準はログ冒頭のとおり（中央値比較）。

### 5. 今回使った特徴的な言い回しを `note/禁止表現.md` に追記
同じ手は二度使わない。

### 6. コミットして push
```
git add note/
git commit -m "note: 第N回 3本の目次と仮説"
git push -u origin claude/nurse-article-theme-analysis-ignzmi
```
push が失敗したら 2s / 4s / 8s / 16s で最大4回リトライ。
**Pull Request は作らない。**

## 分岐の既定値（確認を取らないための表）

| 起きたこと | やること |
|---|---|
| 素材が空 | その章を削除。4章未満なら本ごと中止し記録 |
| 素材が全部空 | 3本とも出さず、ログに「素材未入力」と1行だけ書いて push して終了 |
| 仮説が思いつかない | ログの「次に試す仮説」を使う。それも無ければ本3を出さず記録 |
| 禁止表現を避けられない | 章を書き直す。それでも無理なら章を削除 |
| 型と実績が食い違う | 型を1条件だけ書き換え、ログに残す |
| 前回の記事が未公開 | 判定は「保留」。次回に持ち越す |
| push が競合 | origin をマージして再 push。履歴は書き換えない |
| 判断がつかない | **人間に聞かない。** より保守的な側（出さない・削る）を選び、ログに理由を1行残す |

## やらないこと
- 人間への質問、確認、選択肢の提示
- 素材にない事実の生成
- 本文の執筆（作るのは目次まで）
- Pull Request の作成
- ログの過去行の編集
