# /自動 — note運営を1コマンドで回す

企画からタイトル・価格設計まで、**人間の判断を挟まずに最後まで作る**。
`$ARGUMENTS` にテーマ指定があればそれを使う。無ければ自動で選ぶ。

出力先は `note/output/YYYY-MM-DD/` にまとめる。

---

## 実行前チェック（ここで止まる条件）

1. `note/voice.md` の「失敗・遠回りした経験」「読者」「商品」が埋まっているか。
   → 空欄なら**中断して報告する**。埋まっていない状態で自動実行すると一般論が量産されるだけ。
2. `note/themes/backlog.md` の「公開済み」を読み、**同じ切り口を再利用しない**。

---

## Phase 1｜❺企画（自動選択）

`.claude/skills/note-plan/SKILL.md` に従って候補を12本出し、スコアリングする。

**自動モードの選択ルール：**
- 合計スコア最高のものを選ぶ
- ただし **独自性5点**（＝`voice.md` の失敗談だけで8割書けるもの）を優先する
- 素材が手元に無いテーマ（取材・数字の確認が要るもの）は自動実行では選ばない。候補には残す

選んだ理由と、選ばなかった上位候補を必ず出力する。

## Phase 2｜❶投稿（Threads 10本）

`.claude/skills/note-post/SKILL.md` に従う。10種の型を全部使う。

**自動モードの追加ルール：**
- 10本のうち **3本は今回のテーマの反応テスト**にする（先出しして刺さるか見る）
- 残り7本は独立して成立する投稿にする（noteが公開されなくても使える）
- 10本目の「告知」は、note公開後に使う想定で作る

## Phase 3｜❷執筆（8,000字）

`.claude/skills/note-write/SKILL.md` に従う。

**自動モードでは構成案の承認を取らずに本文まで進む。**
ただし構成案は `01-構成.md` として別ファイルに残す（後から差し戻せるように）。

## Phase 4｜❸編集（自動適用）

`.claude/skills/note-edit/SKILL.md` に従って検出する。

**自動モードでは検出→承認→修正の「承認」を飛ばし、修正まで適用する。**
そのかわり **変更ログを全件残す**（`04-編集ログ.md`：行番号／原文／修正後／理由）。
納得できない修正は後から戻せる状態にしておく。承認を飛ばすのは手間を省くためであって、
勝手に直していい理由ではない。

適用後、AI臭さの再チェックを1回だけ回す（1回目で全部は取れない）。

## Phase 5｜❻販売（タイトル・価格・有料ライン）

`.claude/skills/note-sell/SKILL.md` に従う。
価格は300円／500円の2択。有料ラインは**行番号で指定**する。

---

## 出力

```
note/output/YYYY-MM-DD/
  00-サマリ.md        今回の判断と、人間がやる作業
  01-構成.md          ❷の構成案
  02-本文.md          ❸適用後の完成原稿（有料ライン位置つき）
  03-threads.md       Threads 10本（投稿順つき）
  04-編集ログ.md      ❸が何をどう直したか全件
  05-販売.md          タイトル20案／推薦3案／価格／有料ライン
```

## 最後に必ず出すもの（00-サマリ.md の末尾）

```markdown
## ARYUNさんがやること（これだけ）
1. Threads を上から順に投稿する（推奨：1日1〜2本）
2. 【要確認】◯件 を埋める → 下に一覧
3. note を公開する（タイトル・価格・有料ラインは 05-販売.md のとおり）
4. 3日後に数字を `/分析` に貼る

## 【要確認】一覧
- 02-本文.md 117行目：副業に払った150万の内訳（初期費用と月額の別）
- ...

## 自動実行で判断したこと
- テーマ：◯◯を選んだ（理由）
- 価格：300円にした（理由）
- 編集：42件を自動修正した（内訳）
```

---

## 自動実行でやってはいけないこと

- **数字・日付・固有名詞をでっち上げること。** 分からない箇所は `【要確認】` で穴を空けたまま出す。
  自動だからといって埋めてはいけない。ここを守らないと、この仕組み全体が信用できなくなる。
- **`note/voice.md` を勝手に書き換えること。** 更新できるのは ❹分析担当の「6. 過去の勝ちパターン」だけ。
- **公開済みと同じ切り口を作ること。** `backlog.md` を必ず読む。
- **本人の許可なく実際に投稿すること。** この仕組みは原稿を作るところまで。投稿は人がやる。
