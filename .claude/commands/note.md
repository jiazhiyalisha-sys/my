# /note — 今日やることを決める

「何から手をつければいいか分からない」ときに叩く。

## 手順

1. `note/voice.md` を読む（読者・文体・商品・勝ちパターン）。
2. 今の状態を確認する。
   - `note/analytics/log.csv` の最終行の日付 → 最後に数字を記録したのはいつか
   - `note/drafts/` の最新ファイル → 書きかけの原稿があるか
   - `note/threads/` の最新ファイル → 投稿案の在庫があるか
   - `note/themes/backlog.md` の「候補」欄 → 次のテーマが決まっているか
3. 下の判定表で **次にやる担当を1つだけ** 決めて、理由とともに提案する。
4. 承認されたらそのスキルを実行する。

## 判定表（上から順に当てはめる）

| 状態 | 次にやる |
|---|---|
| 書きかけの原稿があり、まだ編集していない | ❸ `/note-edit` |
| 編集済みの原稿があり、有料ラインが未設定 | ❻ `/note-sell` |
| 公開から3日以上たち、数字が未記録の投稿がある | ❹ `/note-analyze` |
| Threads投稿案の在庫が3本以下 | ❶ `/note-post` |
| 次のテーマが決まっている（backlogに候補あり） | ❷ `/note-write` |
| 上のどれでもない | ❺ `/note-plan` |

## 原則（迷ったらこれを守る）

- **Threadsの反応を見てからnoteを書く。** 反応ゼロのテーマに8,000字かけない。
- **分析したら `note/voice.md` の「6. 過去の勝ちパターン」に書き戻す。** 書き戻さない分析は次に活きない。
- **1日に2担当まで。** ❶〜❻を1日で全部回そうとしない。

## 出力

```markdown
## 現状
- 最後の数値記録：◯月◯日（◯日前）
- 書きかけの原稿：◯件
- Threads在庫：◯本
- 次のテーマ：あり／なし

## 今日やること
❹ 分析担当（/note-analyze）

理由：8月28日公開の記事の数字がまだ入っていない。
ここを飛ばすと、次のテーマを勘で決めることになる。

## 今日はやらないこと
❷ 執筆。テーマが数字で裏付けられていないので、先に❹→❺。
```
