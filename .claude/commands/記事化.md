# /記事化 — タイトル → 完成原稿

タイトルを1本渡すと、**構成・本文・編集まで止まらずに走り切って完成原稿にする。**

```
/記事化 "副業に150万払った日、私は領収書すら貰わなかった"
```

`$ARGUMENTS` が空なら `note/titles/stock.md` の未使用タイトルから、
**確認事項が最も少ないもの**を1本選ぶ（選んだ理由を出力する）。

出力先：`note/drafts/YYYY-MM-DD-{slug}/`

---

## Phase 0｜読む

`note/voice.md`（事実・禁止事項・連載の現在地）と `note/style.md`（文体の実物見本）。
**この2つを読まずに書き始めない。**

## Phase 1｜構成（`01-構成.md`）

`.claude/skills/note-write/SKILL.md` の構成テンプレに従う。

- 章立てと字数配分を決める（合計8,000字）
- **「自分の失敗」と「具体的な手順」は必ず入れる**
- 見出しは箱の名前にしない（「はじめに」「まとめ」は禁止）
- **各章に、その章で使う一次情報（数字・日付・セリフ）を先に列挙する**
  ここで埋まらない章は、本文でも埋まらない。先に `【要確認】` として確定させる

自動モードなので承認は取らずに Phase 2 へ進む。構成はファイルに残すので後から差し戻せる。

## Phase 2｜本文（`02-本文-初稿.md`）

- 8,000字。章ごとの配分を守る
- 一文40〜50字（`voice.md`）。同じ長さを3連続させない
- 読者の口癖（「いや〜」「私なんて...」「だって」）を**そのまま**登場させる
- 各章に数字・固有名詞・日付を最低1つ。出せない箇所は `【要確認：◯◯】` で穴を空けて先へ進む
- 有料ライン候補の位置に `<!-- 有料ライン候補 -->` を置く
- **`voice.md` の禁止事項を守る**：自慢話にしない／読者を否定しない／
  勤務先・利用者・同僚が特定される情報を書かない

## Phase 3｜編集（`03-編集ログ.md` → `04-本文-完成.md`）

`.claude/skills/note-edit/SKILL.md` の3レベルで検出し、**承認を飛ばして修正まで適用する。**

- 変更は**全件ログに残す**（行番号／原文／修正後／理由）
- 適用後にもう1回だけ再チェックを回す（1回目で全部は取れない）
- 修正の優先順位は **削る > 言い換える > 足す**
- 文字数の増減を報告する（5〜15%減っていなければ抜けていない）

---

## 完了報告（必ずこの4点を出す）

1. **実測文字数**（`wc -m` 相当。目測で言わない）
2. **`【要確認】` の残数と該当箇所**（行番号つき一覧）
3. **一次情報が入っている章の数**／全章数
4. **編集で何件・どのレベルを直したか**（語彙／構造／内容の内訳）

## 次にやること（報告の末尾に出す）

```markdown
1. 【要確認】◯件を埋める（下記一覧）
2. /販売 で価格と有料ラインを決める
3. /投稿 でThreads10本を作る（うち3本はこの記事の反応テスト）
```

---

## やってはいけないこと

- **`【要確認】` を推測で埋めること。** 自動で走り切るのは手順であって、事実の補完ではない。
  金額・日付・セリフが記事の信用の源なので、ここを埋めた瞬間に全部が疑わしくなる。
- **8,000字に足りないぶんを一般論で水増しすること。** 足りないなら章を削って構成を組み直す。
- 公開済み記事と同じ切り口で書くこと（`note/themes/backlog.md` を確認する）。
