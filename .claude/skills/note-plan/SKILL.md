# ❺ 企画担当 — 次に書くテーマの候補出し

## 手順

1. `note/voice.md`（特に「失敗・遠回りした経験」「読者」「商品」）を読む。
2. `note/analytics/log.csv` と直近の分析レポートを読む。**反応が実証済みのネタを優先する。** ゼロから思いつきで出さない。
3. `note/themes/backlog.md` の既出テーマを確認し、重複を避ける。
4. 候補を12本出す → スコアリング → 上位5本を詳細化。
5. `note/themes/backlog.md` に追記する。

## ネタの取り出し口（この順で探す）

1. **伸びたThreads投稿** … 需要が数字で実証済み。最優先。
2. **自分の失敗談** … 競合が書けない。`voice.md` から拾う。
3. **読者から実際に来た質問・DM** … そのまま見出しになる。
4. **自分が過去に検索して答えが無かったこと** … 空白地帯。
5. **業界の定説への違和感** … 逆張り記事の種。
6. **数値を持っている領域** … 実測データは他人が書けない。

思いつきの「〇〇のコツ10選」は出さない。上のどれにも当てはまらないネタは候補に入れない。

## スコアリング（各5点、合計15点）

| 軸 | 見るところ |
|---|---|
| **需要** | 検索される／同種の投稿が伸びている／読者から実際に聞かれた |
| **独自性** | 自分の一次情報（数字・失敗・実体験）で8割書けるか |
| **収益接続** | `voice.md` の商品に自然につながるか。有料化できるか |

- 独自性2点以下は、需要が高くても採用しない（一般論記事になる）。
- 収益接続が0点でも、需要5点＋独自性5点なら「集客用」として採用可。

## 出力フォーマット

```markdown
# テーマ候補 YYYY-MM-DD

## スコア表
| # | テーマ（仮題） | 需要 | 独自性 | 収益 | 計 | 出所 |
|---|---|---|---|---|---|---|
| 1 | 40万円溶かした集客の失敗 | 5 | 5 | 4 | 14 | 伸びたThreads#3 |
| 2 | ... | | | | | |

## 上位5本の詳細

### 1. 副業に150万払って騙された話（14点）
- **読者**：副業を手当たり次第に試して、どれも3ヶ月で辞めている20代後半〜30代
- **読者の疑問**：この教材にお金を出していいのか、判断する基準がない
- **自分だけが書けること**：支払った金額・時期・信じた理由・気づいた瞬間
- **主張**：（1行で。反論されうる形にする）
- **無料/有料**：有料300円／無料部分は「支払うまで」の全容、有料は「何を見落としたか」
- **必要な素材**：当時の日付、支払額の内訳、やりとりの記憶
- **Threads先出し**：可（反応を見てから執筆判断）
- **想定字数**：8,000字

## 次のアクション
- 即書ける：#1、#4
- 素材集めが必要：#2（数字の確認が要る）
- 保留：#7（独自性2点。書くなら取材が必要）
```

## 運用ルール

- 候補は12本出す。少ないと選べない、多いと選ばない。
- **1本は必ず「怖くて書けないネタ」を入れる。** 一番伸びるのはそこ。
- 採用したテーマは `note/themes/backlog.md` で `[執筆中]` `[公開済み]` を管理し、同じ切り口を再利用しない。
- 決まったら ❷ライター（`/note-write`）へ渡す。
