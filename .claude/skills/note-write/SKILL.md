# ❷ ライター — note本文 8,000字

## 手順

1. `note/voice.md` と **`note/style.md`（公開済み記事から抽出した文体の実物見本）** を読む。
   **`voice.md` の「失敗・遠回りした経験」と「実績で出せる数字」が空欄なら、先に聞く。** ここが無いと8,000字は必ず一般論で埋まる。
2. 構成案を先に出して**承認を取る**。いきなり本文を書かない。
3. 承認後、`note/drafts/YYYY-MM-DD-{slug}.md` に本文を書く。
4. 書き終わったら文字数を実測して報告する（`wc -m` 相当。目測で報告しない）。
5. そのまま ❸編集担当（`/note-edit`）に渡すよう促す。**初稿は完成品ではない。**

## 構成テンプレ（8,000字の配分）

| 章 | 役割 | 字数 |
|---|---|---|
| 導入 | 読者の現状を名指しする。1行目で「自分のことだ」と思わせる | 600 |
| 1章：問題の再定義 | 読者が思っている原因が違う、と示す | 1,200 |
| 2章：自分の失敗 | いつ・いくら・何を失ったか。ここが記事の信用の源 | 1,500 |
| 3章：転換点 | 何に気づいたか。1つだけ | 1,000 |
| 4章：具体的な手順 | 再現できる粒度。手順・数値・ツール名 | 2,200 |
| 5章：やってはいけないこと | 失敗パターン3つ | 900 |
| 締め | 読者が今日やる1アクション | 600 |

テーマによって章は組み替えてよいが、**「自分の失敗」と「具体的な手順」は必ず入れる**。

## 執筆ルール

- **見出しは内容を言う。**「はじめに」「まとめ」のような箱の名前を付けない。
  - ✕ 2章：私の経験　→　○ 2章：40万円かけて集めた見込み客が、1人も買わなかった
- **数字・固有名詞・日付を各章に最低1つ。** 出せない箇所は `【要確認：○○】` と穴を空けて先へ進む。埋めた気にしない。
- **段落の長さをばらす。** 1行段落を意図的に混ぜる。
- **1章に1つだけ「読者が言い返してきそうな反論」に答える。**
- 比喩は1記事に2つまで。多いと中身が薄まる。
- 箇条書きは全体の2割まで。8,000字が箇条書きの羅列になったら失敗。

## 有料noteの場合

- 有料ラインより **前** に「効果の証明」を置く（結果・実例・なぜ効くか）。
- 有料ラインより **後** に「やり方」を置く（手順・テンプレ・数値・失敗回避）。
- 無料部分だけで読み切れてしまう構成にしない。逆に、無料部分に価値が無いのもダメ。
- ライン位置の最終決定は ❻販売担当（`/note-sell`）。ライターは候補位置に `<!-- 有料ライン候補 -->` を置くだけでよい。

## 完了報告に必ず含める

- 実測文字数
- `【要確認】` の残数と箇所
- 一次情報（自分にしか書けない事実）が入っている章の数
